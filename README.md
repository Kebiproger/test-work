# Flower Shop 🌸

Добро пожаловать в репозиторий интернет-магазина цветов. Проект построен на микросервисной архитектуре и полностью упакован в Docker для легкого старта и развертывания.

## 🏗 Архитектура проекта

Проект состоит из 4 основных контейнеров (сервисов), описанных в `docker-compose.yml`:

### 1. Backend (`backend`)
- **Стек:** Python 3.10, FastAPI, SQLAlchemy (Async), Alembic, Uvicorn.
- **Роль:** Отвечает за бизнес-логику, работу с базой данных и обработку загружаемых файлов (картинок).
- **Особенности:** 
  - При запуске контейнера автоматически применяются миграции БД (`alembic upgrade head`).
  - Имеет два набора API: публичный (витрина) и приватный (админка, защищенная `X-API-Key`).
  - Сохраняет загруженные изображения в локальную папку `/app/media`, которая синхронизируется через Docker Volume.

### 2. Frontend (`frontend`)
- **Стек:** Nginx (Alpine), SPA (React/Vue/Angular - разрабатывается).
- **Роль:** Раздает статические файлы клиентского приложения и проксирует запросы.
- **Особенности:**
  - Слушает порт `80`.
  - Все запросы, начинающиеся с `/api/v1/`, Nginx автоматически проксирует на `backend:8000` (что полностью исключает проблемы с CORS).
  - Все запросы, начинающиеся с `/media/`, Nginx отдает напрямую из расшаренного Docker Volume, не нагружая бэкенд.

### 3. Database (`db`)
- **Стек:** PostgreSQL 15 (Alpine).
- **Роль:** Основное хранилище данных (товары, цены, наличие).
- Данные сохраняются персистентно благодаря Docker Volume `pg_data`.

### 4. Database UI (`pgweb`)
- **Стек:** Pgweb.
- **Роль:** Удобный веб-интерфейс для просмотра и редактирования базы данных прямо в браузере.
- Доступен по порту `8081`.

## 📂 Как работают медиафайлы (Картинки)

Одна из ключевых фичей архитектуры — эффективная раздача загруженных изображений:
1. Админ загружает картинку через POST-запрос к бэкенду.
2. Бэкенд сохраняет файл в `/app/media/уникальное_имя.jpg` и пишет в БД путь `/media/уникальное_имя.jpg`.
3. Папка `/app/media` связана с Nginx через общий Docker Volume `media_files`. Nginx видит эти файлы по пути `/usr/share/nginx/html/media`.
4. Когда клиент (браузер) запрашивает `http://localhost/media/...`, Nginx отдаёт файл напрямую со скоростью статики.

## 🚀 Запуск проекта

Убедитесь, что у вас установлены **Docker** и **Docker Compose**.
В корне проекта создайте файл `.env` (если его нет) с нужными переменными окружения:
```bash 
cp .env.example .env
```
или 
```env
POSTGRES_USER=postgres
POSTGRES_PASSWORD=secret
POSTGRES_DB=flower_db
DATABASE_URL=postgresql+asyncpg://postgres:secret@db:5432/flower_db
ADMIN_API_KEY=your_secret_api_key
```

Запуск всех сервисов в фоновом режиме:
```bash
docker compose up --build -d
```

### Доступные адреса после запуска:
- **Сайт (Фронтенд):** [http://localhost](http://localhost)
- **API Swagger Документация:** [http://localhost:8000/docs](http://localhost:8000/docs)
- **Pgweb (База данных):** [http://localhost:8081](http://localhost:8081)

## 🔧 Структура API

- **Публичное API:** `/api/v1/public/...` (открыто для всех).
- **Админское API:** `/api/v1/admin/...` (требует передачи HTTP-заголовка `X-API-Key`, совпадающего с `ADMIN_API_KEY` в `.env`).
