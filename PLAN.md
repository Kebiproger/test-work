# Flower Shop Frontend — план работ

Бэкенд (FastAPI + Postgres) уже реализован и является фиксированным контрактом.
Фронтенда нет: `frontend/src/main.js` пустой, `package.json` содержит
заглушку `build`. Это план на реализацию фронтенда с нуля под существующий API.

## Дизайн

Готовый дизайн-макет лежит в `design/` (см. `design-system.txt`):
- `design/Флора - экраны.dc.html` — открыть в браузере. 8 экранов, каждый
  подписан конкретной ручкой бэкенда, которую он использует.
- `design/_ds/nocturne-.../styles.css` + `readme.md` — сама дизайн-система
  (токены цвета/типографики/spacing/radius/shadow как CSS-переменные,
  классы компонентов, разбор состояний). Верстать нужно на этих токенах,
  а не изобретать свои.

## Найденные проблемы в текущем репозитории

Пункты 1, 6, 7, 8 уже исправлены в этой ветке (см. git log) — окружение
и бэкенд-контракт были в рабочем состоянии до начала фронтенд-разработки.
Остальное — то, с чем предстоит работать во фронтенде.

1. ✅ ~~Баг в `backend/app/api/public_api.py`~~ — обе публичные ручки вызывали
   `services.get_products` / `get_product` (без фильтра), а не
   `get_public_products` / `get_public_product`, из-за чего витрина
   показывала скрытые товары. Исправлено; заодно добавлена
   `GET /api/v1/admin/products` (без фильтра) — админке нужен способ увидеть
   и снова включить скрытый товар.
2. **Нет `total` в ответе списка товаров** → нормальную постраничную навигацию
   не построить, только `skip/limit` → делать «Показать ещё» / infinite scroll.
3. **Нет поиска/фильтра/сортировки на бэке** → реализовать на клиенте.
4. **Корзины на бэке нет** — `backend/app/api/cart.py` целиком закомментирован.
   Корзина и оформление заказа — только клиентские (localStorage). На
   экранах дизайна (04 — «Оформление заказа») это явно проговорено.
5. **CORS не настроен** (`app.main` без `CORSMiddleware`) → в dev обязателен
   Vite-прокси на `/api/v1` и `/media` (на что бы ни был собран фронт).
6. ✅ ~~`/media` не раздаётся в dev~~ — добавлен `StaticFiles` mount в
   `backend/app/main.py`.
7. ✅ ~~`frontend/Dockerfile` на `node:18-alpine`~~ — поднято до `node:20-alpine`
   (нужно для современных версий Vite).
8. ✅ ~~`docker-compose.yml` пробрасывал фронт на `127.0.0.7:80`~~ — на macOS
   этот алиас не слушается по умолчанию, из-за чего `http://localhost` не
   открывался. Исправлено на `127.0.0.1:80`.
9. `Decimal` из Pydantic приходит в JSON строкой (например, `"price":
   "1500.00"`) — парсить в `number` один раз на границе API-слоя, а не
   передавать строку дальше по компонентам.

## Этапы

### E0 — Фундамент
- Инициализация Vite-проекта (или другого стека на выбор) в `frontend/`,
  снос заглушки `build`.
- Proxy dev-сервера на `/api/v1` (и `/media`, если фронт не проксирует его
  отдельно) → `http://localhost:8000`.
- `/media`, node-версия в Dockerfile и порт в `docker-compose.yml` уже
  починены (п.6–8) — просто проверить, что `docker compose up --build`
  поднимает всё и `http://localhost` открывается.
- ESLint + Prettier, алиас `@/`, `.editorconfig`.

### E1 — API-слой и типы
- Генерация типов из OpenAPI (`openapi-typescript`).
- Тонкий HTTP-клиент: базовый URL, `X-API-Key` для админки, разбор ошибок
  FastAPI (`{detail: "..."}`), типизированный `ApiError`.
- Нормализация `price` (string|number → number) на границе.
- Query keys фабрикой, разумные `staleTime`/`retry` в `QueryClient`.

### E2 — Дизайн-система
Готовая дизайн-система лежит в `design/` (см. раздел «Дизайн» выше) — не
изобретать новую, а перенести токены и классы оттуда в свой стек (CSS
custom properties → CSS Modules/Tailwind/styled-components, на выбор).
- Импортировать/повторить токены из `styles.css`: цвета (тёмная тема,
  тональные рампы 100–900), типографика (Inter, шкала h1–h6), spacing
  (компактная плотность 0.7×), radius, shadow.
- Компоненты по `readme.md`: `.btn` (primary/secondary/ghost/icon/block),
  `.tag`, `.field`+`.input`, `.radio`, `.seg`, `.card`, `.nav`, `.table`,
  `.dialog`. Разметка каждого — прямо в `design/_ds/.../components/*.html`
  (смотреть исходники, а не гадать).
- Страница `/ui-kit` (или аналог) — живой каталог перенесённых токенов и
  компонентов, чтобы проверять их в изоляции.
- A11y с самого начала: `:focus-visible` (2px accent ring — уже описано в
  дизайне), фокус-трап в диалоге, Esc, навигация с клавиатуры.

### E3 — Витрина
- Грид карточек, `Skeleton`/`EmptyState`/состояние ошибки с retry.
- Фильтр по `product_type`, поиск по названию, сортировка по цене — на
  клиенте, состояние в URL (`?type=&q=&sort=`).
- «Показать ещё» вместо нумерованной пагинации (нет `total`).
- `stock_quantity === 0` → бейдж «Нет в наличии», кнопка задизейблена.
- Картинки: `loading="lazy"`, фиксированный `aspect-ratio`, плейсхолдер/фолбэк.

### E4 — Карточка товара
- `/products/:id`, полноценное 404-состояние.
- Счётчик количества с потолком по `stock_quantity`, «В корзину».

### E5 — Корзина
- Zustand + persist, схема с полем `version`.
- Страница корзины: количество, удаление, итог, пустое состояние.
- Ревалидация при открытии (актуальные цена/наличие по API).
- Оформление заказа: форма (zod) → экран успеха; в README — явное указание,
  что заказ хранится только локально (см. п.4).

### E6 — Админка
- `/admin` за `X-API-Key` (sessionStorage), 401/403 → форма ключа заново.
- Список берётся из `GET /api/v1/admin/products` (видны и неактивные).
- Создание: форма + drag&drop, превью, `FormData` без ручного `Content-Type`.
- Редактирование (`PUT`), inline-правка остатков (`PATCH /stock`), удаление
  с подтверждением.
- Оптимистичные апдейты + инвалидация кэша, toast на успех/ошибку.
- В README — честно про то, что ключ доступен в браузере (ограничение бэка).

### E7 — Качество
- Vitest: store корзины, `formatPrice`, пара компонентных тестов через MSW.
- `ErrorBoundary`, страница 404.
- Мобильная вёрстка, проверка на 360px.
- `frontend/README.md`: запуск, принятые решения, найденные баги бэка,
  что сделал бы дальше.

### E8 — Docker
- `docker compose up --build` целиком, проверка прод-сборки на `http://localhost`.

## Порядок выполнения

E0 → E1 → E2 → E3 → E4 → E5 → E6 → E7 → E8.
При нехватке времени в первую очередь режется E7 и глубина E2 —
но `/ui-kit` стоит оставить в любом случае.
