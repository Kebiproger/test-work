# Flower Shop Frontend — план работ

Бэкенд (FastAPI + Postgres) уже реализован и является фиксированным контрактом.
Фронтенда нет: `frontend/src/main.js` пустой, `package.json` содержит
заглушку `build`. Это план на реализацию фронтенда с нуля под существующий API.

## Стек

| Слой | Выбор | Зачем |
|---|---|---|
| База | React 18 + TS + Vite | ложится на существующий `frontend/Dockerfile` (`npm run build` → `dist`) |
| Серверное состояние | TanStack Query | кэш, retry, инвалидация, loading/error из коробки |
| Клиентское состояние | Zustand + persist | корзина в localStorage |
| Роутинг | React Router | |
| Формы | react-hook-form + zod | валидация формы товара и оформления заказа |
| Стили | CSS Modules + CSS-переменные (токены) | своя дизайн-система вместо утилитных классов |
| Тесты | Vitest + Testing Library + MSW | |

## Найденные проблемы в текущем репозитории

1. **Баг в `backend/app/api/public_api.py`** — обе публичные ручки (`list_products`,
   `read_product`) вызывают `services.get_products` / `get_product`, а не
   `get_public_products` / `get_public_product`. В результате не применяется
   фильтр `is_active` и витрина показывает скрытые товары. Правильные функции
   уже написаны в `repositories.py`, но не подключены.
   → Обойти на клиенте (фильтровать `is_active` самостоятельно) и описать в README,
   либо починить бэк отдельным маленьким коммитом.
2. **Нет `total` в ответе списка товаров** → нормальную постраничную навигацию
   не построить, только `skip/limit` → делать «Показать ещё» / infinite scroll.
3. **Нет поиска/фильтра/сортировки на бэке** → реализовать на клиенте.
4. **Корзины на бэке нет** — `backend/app/api/cart.py` целиком закомментирован.
   Корзина и оформление заказа — только клиентские (localStorage).
5. **CORS не настроен** (`app.main` без `CORSMiddleware`) → в dev обязателен
   Vite-прокси на `/api/v1`.
6. **`/media` не раздаётся в dev** — nginx раздаёт файлы из volume только в
   контейнере. В FastAPI нет `StaticFiles` mount на `/media`.
   → либо добавить `app.mount("/media", StaticFiles(directory=settings.MEDIA_PATH))`
   в `backend/app/main.py`, либо проксировать на поднятый контейнер фронта.
7. **`frontend/Dockerfile`** использует `node:18-alpine` — Vite 7 требует
   Node 20.19+, стоит поднять базовый образ.
8. **`docker-compose.yml`** пробрасывает фронт на `127.0.0.7:80`, а README
   обещает `http://localhost` — расхождение, нужно поправить одно из двух.
9. `Decimal` из Pydantic может прийти в JSON строкой — парсить price в number
   один раз на границе API-слоя.

## Этапы

### E0 — Фундамент
- Инициализация Vite-проекта в `frontend/`, снос заглушки `build`.
- `vite.config.ts`: proxy `/api/v1` → `http://localhost:8000`.
- Решение проблемы с `/media` в dev (см. п.6 выше).
- `node:18-alpine` → `node:20-alpine` в Dockerfile.
- ESLint + Prettier, алиас `@/`, `.editorconfig`.

### E1 — API-слой и типы
- Генерация типов из OpenAPI (`openapi-typescript`).
- Тонкий HTTP-клиент: базовый URL, `X-API-Key` для админки, разбор ошибок
  FastAPI (`{detail: "..."}`), типизированный `ApiError`.
- Нормализация `price` (string|number → number) на границе.
- Query keys фабрикой, разумные `staleTime`/`retry` в `QueryClient`.

### E2 — Дизайн-система
- Токены (`tokens.css`): семантические роли цвета, типографика, spacing 4pt,
  radius, shadow, motion. Светлая/тёмная тема.
- Примитивы: `Button`, `Input`, `Textarea`, `Select`, `Badge`, `Card`,
  `Skeleton`, `Dialog`, `Toast`, `EmptyState`, `Spinner`, `FileDropzone`.
- Страница `/ui-kit` — живой каталог токенов и компонентов.
- A11y с самого начала: `:focus-visible`, `aria-label`, фокус-трап, Esc,
  навигация с клавиатуры.

### E3 — Витрина
- Грид карточек, `Skeleton`/`EmptyState`/состояние ошибки с retry.
- Фильтр по `product_type`, поиск по названию, сортировка по цене — на
  клиенте, состояние в URL (`?type=&q=&sort=`).
- «Показать ещё» вместо нумерованной пагинации (нет `total`).
- Клиентская фильтрация `is_active` (обход бага п.1).
- `stock_quantity === 0` → бейдж «Нет в наличии», кнопка задизейблена.
- Картинки: `loading="lazy"`, фиксированный `aspect-ratio`, плейсхолдер/фолбэк.

### E4 — Карточка товара
- `/products/:id`, полноценное 404-состояние.
- Счётчик количества с потолком по `stock_quantity`, «В корзину».

### E5 — Корзина
- Zustand + persist, схема с полем `version`.
- Страница корзины: количество, удаление, итог, пустое состояние.
- Ревалидация при открытии (актуальные цена/наличие по API).
- Оформление заказа: форма (zod) → экран успеха; в README — явное указание,
  что заказ хранится только локально (см. п.4).

### E6 — Админка
- `/admin` за `X-API-Key` (sessionStorage), 401/403 → форма ключа заново.
- Список берётся из публичной ручки (см. зависимость от бага п.1).
- Создание: форма + drag&drop, превью, `FormData` без ручного `Content-Type`.
- Редактирование (`PUT`), inline-правка остатков (`PATCH /stock`), удаление
  с подтверждением.
- Оптимистичные апдейты + инвалидация кэша, toast на успех/ошибку.
- В README — честно про то, что ключ доступен в браузере (ограничение бэка).

### E7 — Качество
- Vitest: store корзины, `formatPrice`, пара компонентных тестов через MSW.
- `ErrorBoundary`, страница 404.
- Мобильная вёрстка, проверка на 360px.
- `frontend/README.md`: запуск, принятые решения, найденные баги бэка,
  что сделал бы дальше.

### E8 — Docker
- `docker compose up --build` целиком, проверка прод-сборки.
- Исправить расхождение `127.0.0.7` vs `localhost` (п.8).

## Порядок выполнения

E0 → E1 → E2 → E3 → E4 → E5 → E6 → E7 → E8.
При нехватке времени в первую очередь режется E7 и глубина E2 —
но `/ui-kit` стоит оставить в любом случае.
